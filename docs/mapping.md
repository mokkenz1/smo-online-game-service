# Маппинг домена на элементы СМО

**Сервис обработки действий игроков на сервере онлайн-игры**
Вариант № 15 · Лебедев Александр Михайлович · группа 5130904/40101

| Элемент СМО | Сущность бизнес-домена | Назначение |
|---|---|---|
| **Источник** | Игровой клиент (компьютер/устройство игрока) | Непрерывно генерирует запросы на обработку игровых действий и передаёт их на сервер. Каждый игрок может отправлять множество запросов за время сессии; поток запросов считается бесконечным. |
| **Заявка** | Запрос на обработку игрового действия (игровой тик) | Единица информации о конкретном действии игрока: движение, атака, использование предмета и т. п. Содержит номер источника (игрока) и его приоритет, тип действия, момент поступления. Ожидает в буфере, если все обработчики заняты. |
| **Буферная память** | Кольцевой буфер запросов, ожидающих обработки | Временно хранит запросы, которые не могут быть немедленно переданы на обработчик. Реализован как кольцевая структура: поиск свободного места ведётся от указателя, установленного на ячейку, следующую за последней занятой. |
| **Прибор** | Обработчик (поток/ядро игровой логики) сервера | Выполняет обработку запроса: проверяет корректность действия, обновляет состояние игрового мира, формирует ответ клиенту. Время обработки равномерно распределено (соответствует стабильному игровому тику). |
| **Диспетчер постановки** | Компонент приёма и размещения запросов в буфере | Размещает поступивший запрос в буфере «по кольцу» (Д1ОЗ1): начиная с указателя ищет первое свободное место, при достижении конца буфера продолжает поиск с начала. При отсутствии свободных мест применяет дисциплину отказа Д1ОО2 — выбивает запрос от источника с наименьшим приоритетом. |
| **Диспетчер выбора** | Планировщик обработки запросов | Выбирает из буфера пакет запросов от наиболее приоритетного на данный момент источника (Д2Б5) и передаёт их последовательно свободному обработчику, выбираемому по приоритету номера прибора (Д2П1). |
| **Отказ** | Уведомление о потере действия (десинхронизации) | При переполнении буфера отклоняется запрос от источника с наименьшим приоритетом среди находящихся в буфере; на его место встаёт новый запрос. Игрок получает уведомление: «Действие не обработано, задержка сети». |
| **Обслуживание** | Обработка действия сервером (обработчиком игровой логики) | Обработчик проверяет корректность действия, применяет изменения к игровому миру, формирует и отправляет результат клиенту(ам). После этого заявка покидает моделируемую систему. |
| **Выход из системы** | Обработанное или отклонённое игровое действие | Запрос покидает систему после успешного применения действия к игровому миру либо в результате отказа (выбивания из буфера). |
