# Сервис обработки действий игроков на сервере онлайн-игры

**Моделирование системы массового обслуживания (СМО)**
**Вариант № 15** · Лебедев Александр Михайлович · группа 5130904/40101

## О задаче

Разработка сервиса, обеспечивающего приём и обработку запросов на игровые действия (перемещение, атака, способности, предметы, чат), поступающих от клиентов игроков на сервер онлайн-игры, с учётом ограниченной пропускной способности серверных обработчиков.

- [Бизнес-домен](docs/domain.md)
- [Маппинг домена на элементы СМО](docs/mapping.md)

## Формула варианта СМО

`ИБ — ИЗ1 — ПЗ2 — Д1ОЗ1 — Д1ОО2 — Д2П1 — Д2Б5 — ОР1 — ОД3`

| Код | Описание | В домене |
|---|---|---|
| **ИБ** | Бесконечный источник | Игровой клиент генерирует действия всю сессию |
| **ИЗ1** | Пуассоновский закон поступления заявок, τ = −ln(r)/λ | Интервалы между действиями игрока |
| **ПЗ2** | Равномерный закон обслуживания, t = a + (b − a)·r | Длительность игрового тика с разбросом |
| **Д1ОЗ1** | Постановка в буфер «по кольцу» от указателя | Кольцевой буфер запросов (ring buffer) |
| **Д1ОО2** | Отказ по приоритету номера источника (выбивается заявка с наименьшим приоритетом; при равенстве — самая старая) | Первым теряется действие игрока с базовым статусом |
| **Д2П1** | Выбор прибора по приоритету номера (с №1) | Обработчик №1 — самый приоритетный |
| **Д2Б5** | Выбор заявок пакетом по приоритету номера источника | Подряд обрабатываются все действия самого приоритетного игрока |
| **ОР1** | Автоматический режим — сводная таблица результатов | Отказы, время ожидания, загрузка обработчиков |
| **ОД3** | Пошаговый режим — временные диаграммы и текущее состояние | Поступления, обработка, состояние буфера на каждом шаге |

## Маппинг (кратко)

| Элемент СМО | Сущность домена |
|---|---|
| Источник | Игровой клиент |
| Заявка | Запрос на игровое действие |
| Буфер | Кольцевой буфер запросов |
| Прибор | Обработчик игровой логики (поток/ядро) |
| Диспетчер постановки | Компонент приёма и размещения запросов |
| Диспетчер выбора | Планировщик обработки запросов |
| Отказ | «Действие не обработано, задержка сети» |

## Принятые проектные решения

- Приоритет определяется номером: **меньший номер — выше приоритет** (и для источников, и для приборов).
- **Диспетчер постановки** работает только с буфером и ничего не знает о приборах; после постановки заявки он генерирует событие для диспетчера выбора.
- **Триггеры диспетчера выбора:** событие «заявка поставлена в буфер» и событие «прибор освободился».
- **Пакет (Д2Б5)** формируется в момент выбора заявки и не расширяется; внутри пакета заявки выбираются по FIFO. Если заявку пакета выбили из буфера, она удаляется и из пакета.
- **Указатель УБ** после постановки (в том числе на место выбитой заявки) устанавливается на следующее место: `УБ = (j + 1) mod N`.
